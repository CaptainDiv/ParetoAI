# Demand Weight is the mean over the Sources entitled to weigh a skill

Each Source reports demand on its own scale, so the Analyst first reads every report as a fraction of that scale: a **Rating** (O*NET's 0–100 task importance) as `rating / maximum`, a **Rank** (OWASP's SC01–SC10) linearly as `(count − rank + 1) / count`, and a Source with **no scale** (Cyfrin's exam objectives) as no weight at all. A skill's **Demand Weight** is then the mean of those fractions over the Sources *entitled to weigh it*: every Source with a scale that cites it, plus every Source with a scale that measures the whole Target Skill and does not cite it, whose silence counts as 0. A Source that measures one part of the Target Skill is left out of a skill it is silent on rather than read as 0. That is the `CONTEXT.md` rule — *a skill's absence from a Source counts against it only if that Source measures the whole Target Skill* — turned into arithmetic: a mean is the combination under which scope changes the answer at all, because leaving a Source out shrinks the denominator rather than merely adding nothing.

## Considered Options

- **Sum the fractions** — rejected: a missing report adds 0 whether the Source covers the whole Target Skill or only a part of it, so the rule above would have no effect. It also rewards being named by more Sources, which brings back the mention count ADR-0003 retired, in a weighted disguise.
- **Take the maximum fraction** — rejected: no Source's silence ever counts, so the OWASP Top 10's first place (1.0) would outrank O*NET's most important task (0.92) on the strength of one security list, which is the security-bias trap ADR-0003 warns about.
- **Mean over the citing Sources only** — rejected: the same flaw as the maximum. Silence from a whole-skill Source is evidence the rule says to count, and this ignores it.

## Consequences

- **The one whole-skill Source with a scale dominates the ranking.** With the configured Sources that is O*NET, so every skill only the OWASP Top 10 names is held to at most 0.5. Live runs therefore put O*NET's occupation-level tasks ("failure handlers", "security performance testing") in the entire top 20%. Once the extractor returned every rated task, all 17 of them outranked OWASP's first place, down to "dashboard development" at 0.64. That is the granularity mismatch ADR-0003 predicted, now load-bearing: O*NET counts as measuring the whole Target Skill, but it never speaks at Solidity level, so its silence on "reentrancy" may say more about its granularity than about demand. Revisit this ADR first if a second whole-skill Source with a scale appears, or if Module topics come out too coarse to teach.
- **Skills named only by a Source with no scale all tie at 0** and sort alphabetically at the bottom. They get into a Curriculum only through prerequisite closure, which in live runs is how "smart contract security fundamentals" reached the Modules.
- **A second Source can lower a skill.** The mean is not monotonic: O*NET at 90 alone gives 0.9, but adding OWASP's tenth place (0.1) gives 0.5. That is what averaging the strength of the reports means, and it is the cost of letting scope count. It bites hardest at the bottom of a ranked list, where a linear Rank reads "tenth of the ten worst failure classes" as nearly no demand.
- **A rank is read as linear** because an ordinal ranking says nothing about the gaps between places. If a Source publishes the scores behind its ranking, give it a Rating instead.
- **One Source naming one skill twice counts once, at its strongest report**, so two O*NET tasks merged onto one skill don't count twice.
- **The extractor is asked for every item a Source with a scale rates, not a sample**, because a whole-skill Source's silence is scored. Leaving out a rated task would turn the extractor's omission into the Source reporting no demand.
- **A citation whose demand the Source's scale can't read is left out, as silence.** Kept unweighed, it would escape a whole-skill Source's 0. The pure core enforces this, records each such citation on `ParetoTable.unreadable_citations`, and the printed table reports them per Source, so a partial shortfall is visible (ADR-0002).
- **A Source that reported nothing readable does not count its silence.** A failed extraction measured nothing, and it shows up as a Source that "contributed nothing".
- **The alias merge refuses after one retry instead of degrading to no merging.** An unmerged skill split across two names leaves the name only a partial Source used taking a whole-skill Source's 0, and nothing shows it (see ADR-0002).
