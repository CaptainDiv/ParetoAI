# A skill takes demand through the Occupational Tasks it serves, and a Rank orders without weighing

ADR-0006 counted O*NET's silence as 0 against every skill it didn't name, because O*NET measures the whole Target Skill. Live, that put all 17 of O*NET's Occupational Tasks, read as skills, above OWASP's first place, so Module topics came out as "risk evaluation" and "dashboard development" (#13). The absence rule really asks *would this Source have named the skill if it were demanded?*, and O*NET never names anything at Module granularity, whatever the demand. Its unit is the **Occupational Task** ("Test the security and performance of blockchain infrastructures"), not a skill. So a Source now declares whether it rates skills or Occupational Tasks. One that rates Occupational Tasks **adds no entries** to the Pareto Table. It weighs each skill the other Sources name through the Occupational Tasks that skill serves, at the strongest rating among them. A skill that serves none of them takes the Source's 0 if it measures the whole Target Skill. That absence means something again, because O*NET's Occupational Tasks span the whole occupation. A model judges which Occupational Task a skill serves; the Source supplies every number.

That made a second flaw systematic. With O*NET reporting about 0.9 for nearly every security skill, averaging in OWASP's linear Rank meant that any place below about second *lowered* a skill. Reentrancy at SC05 scored 0.755, below the same skill left off the Top 10 at 0.91. A place says which comes first, not how much less the last one is worth, so reading "tenth of the ten worst failure classes" as 0.1 invented a level. **A Rank now orders but does not weigh.** Demand Weight is the mean over the Ratings entitled to weigh a skill (ADR-0006's rule, with Ranks removed). Among skills of equal Demand Weight, one a Rank places comes first, in its order, ahead of one it doesn't place. Where several Ranks place a skill, its best place counts: averaging places would read them as levels again, and one more Rank placing a skill low would lower it.

## Considered Options

- **Accept ADR-0006's ranking** — rejected: the cut stays occupation-level, and Rounds can't repair it, since a Gap only maps to a Module already in the Curriculum (noted on #8).
- **Stop counting O*NET's silence (`measures_whole_target_skill=False`)** — rejected: O*NET's Occupational Tasks would still score their own ratings (0.92, 0.91, 0.91, 0.88…) and fill most of the top 8. That doesn't fix the coarse Modules, and it is ADR-0006's rejected "mean over the citing Sources only", which leaves OWASP unchecked.
- **Find a second whole-skill Source with a scale** — rejected for now: the research found none for this Target Skill.
- **Keep the linear Rank in the mean, or give it a floor** — rejected: both read a level into an ordinal list. A floor invents a constant and still lowers skills below O*NET's level.
- **Let a partial Source raise a skill but never lower it** — rejected: only OWASP's first place or two would ever lift anything, and the rest of its order would collapse into alphabetical ties.

## Consequences

- **The Pareto Table holds only skills.** Live, every entry is at Solidity level ("reentrancy protection", "upgradeable smart contracts", "account abstraction"), and Cyfrin's skills, previously stuck at 0, are weighed for the first time.
- **O*NET's numbers come in tiers.** Only some of its 17 Occupational Tasks are Solidity-level work (failure handling and testing 91, threat assessment 88, secure design patterns 85, cryptographic protocols 83, maintainable code base 75, finance 65), so skills share a handful of Demand Weights (8 across 21 entries on 2026-10-11), and OWASP's order decides within a tier. A security tilt at the top of the cut follows from O*NET rating security work highest, not from which Sources were chosen.
- **The model's choice of Occupational Task now moves a weight**, so it is shown. Each entry records the Occupational Tasks it was weighed through, the printed table shows the strongest, and it lists the Occupational Tasks no skill serves, which are the parts of the job this table doesn't reach (O*NET's top-rated Occupational Task, planning with solution architects, among them). Runs vary. The prompt asks for the one Occupational Task a skill most directly serves, adding a second only if it is just as central. A looser "every task it is used for" let nearly every skill claim the top-rated Occupational Task and flattened the table to 0.91. The strongest-rating rule still applies when the model names two, and the builder signed off on this reading on 2026-10-11.
- **"Serves none" is read only from an explicit answer.** The model answers with numbers from the list, so it can't misquote an Occupational Task. A skill it leaves out, or gives a number not on the list, is asked about once more. If it is still unanswered, the Analyst refuses (ADR-0002) rather than hand it a 0 the Source never gave, and the pure core refuses a skill it was given no answer for.
- **Occupational Tasks are extracted word for word**, since a paraphrase once turned "Discuss and plan systems with solution architects…" into "security audits". Every rated one is extracted, as ADR-0006 already required.
- **A Source with no Demand Scale is asked for every objective**, not 5–10: its skills are now weighed, so one left out is demand lost.
- **A Rank-only Target Skill would rank purely by order**, with every Demand Weight at 0. That is honest: no Source said how much.
- **Revisit this if a Source rates skills at Module granularity on a numeric scale.** It would weigh skills directly, and the Occupational Task path would become the coarser of two signals.
