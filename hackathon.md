# ParetoAI

## Project
**Name:** ParetoAI
**Purpose:** An AI agent team that curates a beginner-friendly "20% Pareto" curriculum for a given professional skill — the minimal slice of material that covers most of the practical value — and then pressure-tests it by having simulated learners attempt real closed GitHub issues, graded against the merged fix.
**Problem it addresses:** Beginners drown in exhaustive syllabi before they've validated they can actually apply anything. ParetoAI identifies the highest-leverage subset of a curriculum and verifies comprehension through hands-on coding-issue exercises instead of passive reading or quizzes.

## Stack
- **Language/runtime:** Python 3.11, venv-managed
- **LLM provider:** Groq (OpenAI-compatible API, `https://api.groq.com/openai/v1`), accessed via the `openai` Python client
  - Model in use: `openai/gpt-oss-20b` (chosen after `llama-3.3-70b-versatile` returned 404 — not available on this key; verified available models via `client.models.list()`)
- **Tracing:** neatlogs SDK (`neatlogs[anthropic]` extra installed, though provider is now Groq/OpenAI-compatible), project `209f4402-89cd-450c-9b1d-267a406e4ff6`, workflow name `pareto-ai` (renamed from `pareto-ai-demo` once the Groq+Neatlogs client was centralized in `pareto_ai/llm.py` for every agent to share — one workflow for the whole pipeline, not one per script)
- **GitHub API:** via the authenticated `gh` CLI (`gh api graphql`), used by the Proof-of-Skill sourcing to find merged PRs with formally linked closing issues. Target repo: `OpenZeppelin/openzeppelin-contracts` (MIT, Hardhat suite, squash-merge-only — see the #4 build log entry for why each matters)
- **Embeddings (RAG):** `sentence-transformers` running `all-MiniLM-L6-v2` locally on CPU, over Module content — a Student Agent's retrieval costs no API call and leaves no machine. Install note: `pip install sentence-transformers` on Windows pulls the CUDA build of torch, so install `torch` first from the CPU index (`pip install torch --index-url https://download.pytorch.org/whl/cpu`); the download is slow enough to need `--timeout 120 --retries 10`.
- **Entire:** integrated (ticket #6, closed). Student Agent Attempts run on OpenCode (`entire enable --agent opencode` — a built-in Entire integration, no custom plugin needed), not Gemini CLI as ADR-0001 originally chose; see the 2026-10-11 build log entry and ADR-0005 for why. Verified live: a real commit with a real Entire Checkpoint linked to it (`entire checkpoint explain`).
- **LLM for the Student Agent specifically:** neatHack's own LiteLLM gateway (`https://litellm.vision.aivar.app/v1`, models `nova-micro`/`nova-lite`/`nova-pro`/`nova-2-lite`/`claude-haiku`/`claude-sonnet-4.6`/`claude-opus-4.6`), configured in `opencode.json` at the repo root, key in `.env` as `LITELLM_API_KEY` (gitignored) — not Groq, whose free tier's 8,000 TPM cap is smaller than OpenCode's own baseline prompt regardless of model.
- **Demand Sources (Analyst):** O*NET 15-1299.07 Blockchain Engineers (0–100 task importance; CC BY 4.0, USDOL/ETA — attribution required wherever a table built from it is published), OWASP Smart Contract Top 10 (survey-derived rank 1–10), Cyfrin Updraft SSCD+ exam objectives (no Demand Scale). Plain server-rendered GETs, no auth.
- **cfo.ai:** not yet integrated — required by hackathon rules, pending (tracked as ticket #9). The untracked `docs/business-plan.md` is the brief prepared for the cfo.ai session, not cfo.ai output: the model itself has to be built in cfo.ai, and that session is blocked on cfo.ai account access.
- **Decision records:** `docs/adr/0001` (Gemini CLI for Student Agents), `0002` (refuse LLM degradation that would be invisible), `0003` (a Source is a demand measure, not documentation), `0004` (a custom Entire integration restoring retired Gemini CLI support — works, but superseded as the active engine), `0005` (OpenCode replaces Gemini CLI as the Student Agent engine), `0006` (Demand Weight is the mean over the Sources entitled to weigh a skill)

### 2026-10-10 — Curriculum agent (ticket #3) built; ADR-0002 on failing loudly
- Built `pareto_ai/curriculum.py` (commit `0803a1c`, 44 tests). The LLM is asked only for judgement — hard prerequisite edges, the 1-2 best Resources per topic, which Module a cut entry extends — while the rules that must hold regardless of what it says are pure, TDD'd functions: `select_module_topics` (top ~20% cut, prerequisite closure, ordering) and `assemble_curriculum` (Modules, Resources, Deferred Resources). Resources are planned *after* topic selection, because prerequisite closure is what decides the final topic set.
- **Prerequisite-closure verified live, not just in fixtures:** the Analyst's table ranked "Solidity fundamentals" well outside the top 20%, and closure promoted it to Module 1 — the behaviour `CONTEXT.md` calls non-negotiable.
- **Failure → fix:** `openai/gpt-oss-20b` charges *reasoning* tokens against `max_tokens`. Planning calls spent the whole 2048-token budget thinking and returned `''` (confirmed: `finish_reason=length`, 2046 of 2048 tokens were reasoning). Read as "no prerequisites", that silently switched off prerequisite closure and produced a confident-looking Curriculum whose "top 20%" cut was really *alphabetical*. Fixed with `reasoning_effort="low"` plus a larger budget, and by **refusing** a truncated or unparseable response instead of degrading quietly.
- That failure generalised into **`docs/adr/0003`'s predecessor, `docs/adr/0002`**: degrade only where the degradation shows up in the output; refuse where it would be invisible. Recorded because `analyst.py` degrades silently and `curriculum.py` does not, and the divergence would otherwise read as an oversight.
- **Failure → fix:** the model skips topics on longer lists, leaving a Module with only a bare source name to read. Missing topics are now re-asked for on their own; three consecutive live runs then produced zero link-less Resources.
- Where a prerequisite cycle forces an impossible ordering, the affected Module reports `unmet_prerequisites` rather than reporting none — found by `/code-review`'s Spec axis, which pointed out the original code made an untaught dependency look like *no* dependency.
- Ran `/code-review` (Standards + Spec) before committing; applied 8 findings across the two axes.

### 2026-10-10 — What a Source is, reconsidered (ADR-0003, ticket #11)
- Running the Analyst live showed the ranking measured the wrong thing. Canonical documentation *partitions* a subject rather than surveying it, so **45 of 45 entries tied at frequency 1**, and a skill's score was really decided by which pages a human picked — including three security-ish pages made security topics score 2. The "demand signal" was a readback of the source list.
- Filed as ticket **#11**. Partial fix committed (`9608682`): `canonical_skill` folds case/unicode-dash/punctuation/parenthetical variants, and `merge_skill_aliases` asks the model which differently-worded names mean one skill. The same nudge appended to each page-extraction prompt was reliably ignored behind 5000 chars of page text, so it got its own call — which also removed a source-order dependence.
- **Failure → fix:** six sources plus a Curriculum run exceed Groq's free-tier **8000 tokens/minute**. `pareto_ai/llm.py` now has a single `complete()` that waits out a 429 using the response's own `retry-after`, and carries the reasoning-effort lesson the Analyst had never had (its extraction was burning 427 reasoning tokens against a 1024 budget at default effort).
- The deeper problem was definitional, so it went through `/domain-modeling` rather than more code: **`Source`** was load-bearing in the glossary while never being defined, and "how often they appear" was ambiguous between three different measures. `CONTEXT.md` now defines `Source` (a published measure of market demand) and **`Demand Weight`** (what a Pareto Table ranks on), with `frequency` on its Avoid list. Recorded as **`docs/adr/0003`** (`a3dc501`) so the next reader doesn't "fix" this by adding the Solidity docs back.
- **Research, then a correction to our own ADR** (`b390b41`): `/research` checked the ADR's claims against primary sources and refuted two of them. O*NET *does* have a smart-contract occupation — **15-1299.07 Blockchain Engineers**, updated 2026, publishing 18 tasks and 41 work activities with numeric 0–100 importance ratings, CC BY 4.0. And **no** smart-contract certifier publishes exam weightings, so the ADR's central bet did not pay off. The decision survived; the evidence changed. Findings, with measured fetch offsets, in `docs/research/demand-sources-for-smart-contract-development.md`.
- Two traps that research caught and a length check would not: **W3CB** returns 5,627 bytes of valid-looking HTML yielding **52 characters** of text (a pure SPA shell), and **BLS** returns 403 on `robots.txt` itself with an explicit prohibition — the same category as the job-board scraping the spec already rules out.

### 2026-10-10 — RAG retriever (ticket #5)
- Built `pareto_ai/retrieval.py` (16 new tests, 99 passing). Seam 2, `retrieve(curriculum, query, k)`, over local `all-MiniLM-L6-v2` embeddings — no API call, nothing leaves the machine. The embedder is injected, so the bounding rules are TDD'd pure against fixture Curricula while the real model is exercised separately.
- **The bound, measured live:** a 10-Module Curriculum gave **10 retrievable chunks**, with **34 Deferred Resources linked from those Modules and unreachable** — 10 of 44 Pareto Table entries in reach, which is what makes "bounded to what the Curriculum teaches" a number rather than a claim.
- **Retrieval is semantic, not lexical, and that is tested rather than asserted.** Live, _"a contract keeps calling back into itself before my first call has finished"_ returned **Checks-Effects-Interactions pattern** and **Reentrancy protection** while sharing not one word with either. Three unit tests pin the same property on a fixture and check their own premise: the chunk found has none of the query's words, and the lexical stand-in embedder cannot represent the question at all.
- **What a Chunk may contain was the whole design.** One Chunk per Module — a Module already *is* chunk-sized — carrying its topic, what it assumes, and its Resources. Deferred Resources are excluded because they are exactly the 80% the cut set aside, and retrieving them would bound a Student Agent to the whole Pareto Table again. `CONTEXT.md` gained **Chunk** and the rule that retrieval reaches only what a Module teaches.
- **Failure → fix, caught by `/code-review`'s Spec axis measuring a claim I had only asserted.** `retrieve` dropped chunks scoring `<= 0`, commented as a floor that "almost never fires". The review probed the real embedder: an off-topic question scored a fixture's three chunks at **-0.008, -0.014 and +0.040**, so the sign was noise, the floor was a coin toss, and it admitted +0.040 as relevant regardless. Removed — `k` is the bound the spec names — and recorded as a limitation instead of a threshold invented without calibration data.
- **Failure → fix, ADR-0002 again, from the Standards axis.** A zero vector scores 0 against everything, so an embedder that half-failed would have returned an empty answer that reads exactly like "nothing in this Curriculum covers that" — a claim about the Curriculum, not the embedder, and one that ends up in a pass rate. Now refused loudly as `RetrievalError`.
- **An honest miss in the same live run:** _"my transaction runs out of gas inside a loop"_ returned multi-sig and reentrancy Modules, because this Curriculum has no gas Module at all — the placeholder sources never produced one. Retrieval returns its k nearest chunks and cannot say "nothing here covers that", which is the limitation above, visible in the demo rather than hidden by it.
- **Install friction worth knowing before a demo:** on Windows `pip install sentence-transformers` pulls the CUDA build of torch, so torch comes first from the CPU index; the download then needed `--timeout 120 --retries 10` after a `ReadTimeoutError` killed one attempt mid-way.
- Retrieval is a step inside an Attempt rather than a workflow of its own, so `retrieve` carries a `RETRIEVER` span and the embedder an `EMBEDDING` span (both OpenInference kinds the neatlogs SDK documents), with a `WORKFLOW` root added for standalone runs so the spans are not orphaned.

### 2026-10-11 — Entire integration (tickets #6, #12): a real failure, a real recovery
- **Discovery, not assumption:** ADR-0001 chose Gemini CLI because Entire's checkpoint capture "currently only supports... Claude Code and Gemini CLI." Reading `entireio/cli`'s own source (`cmd/entire/cli/retired_gemini.go`) directly showed that was no longer true — native Gemini CLI support had been retired. Recorded as a correction in **ADR-0004**, not a silent fix: the ADR stands on wrong-at-the-time evidence until this.
- **Built a real fix anyway, not a workaround.** Entire's own retirement code (`retiredGeminiNameClaimed()`) explicitly defers to an external plugin named `gemini` on `$PATH` rather than stripping its hooks — a deliberate seam for exactly this. Built `pareto_ai/entire_agent_gemini.py` + `bin/entire-agent-gemini(.cmd)` against Entire's documented Agent Integration Protocol (11 required commands + the `hooks` capability), reverse-engineered live against gemini-cli 0.63.0's real on-disk session format (a JSONL patch log, not the single JSON object its own transcript compactor expects) and real hook events. Filed as its own ticket (**#12**, closed) since it was real scope the original ticket didn't anticipate.
- **It worked — and then hit a wall that had nothing to do with it.** `entire login`, `entire enable --agent gemini --checkpoint-backend branch`: real hook installation, a real `entire/checkpoints/v1` branch, confirmed live. But Gemini CLI's own Policy Engine denies every `run_shell_command` call under full headless automation — not a configuration miss: `--skip-trust`, `--yolo`, `GEMINI_CLI_TRUST_WORKSPACE=true`, and an explicit `~/.gemini/policies/*.toml` allow rule at priority 999 were all tried, and the identical "Tool execution denied by policy" error reproduced in two independent environments. Every edit-run-commit step an Attempt needs depends on that one call, so this blocked the ticket outright, confirmed rather than guessed at.
- **Found a real open-source project in the same situation and verified what they did, rather than guessing.** Kedge (github.com/faroukobayanju/kedge), a real neatHack submission, solved the identical problem with OpenCode instead — Entire supports it as a built-in agent (no custom plugin). Verified three things independently before switching, not on Kedge's word alone: neatHack's own pages (neatlogs.com/hackathon, /hackathon/models) confirm a real, free-to-the-team LiteLLM gateway ($20 shared budget/30 days, seven real models); OpenCode's actual `--auto`/`--dir`/`-m` flags match what Kedge's code uses; and `opencode-ai@1.18.35` (not the `1.19.0` npm installs by default) is the version whose plugin API Entire's generated plugin actually works with.
- **Two config gotchas that cost real debugging time, now load-bearing comments in the code so they aren't rediscovered:** every model in `opencode.json` needs an explicit `limit.output` (Bedrock Nova's hard cap is 10,000; OpenCode's own default request exceeds it without one — a different, model-specific failure from Groq's TPM error, easy to mistake for the same thing); and `run_opencode_attempt` needs `stdin=subprocess.DEVNULL` (an inherited stdin silently stops OpenCode from loading Entire's plugin at all — no error, just no Checkpoint) plus an explicit `PWD` (OpenCode resolves its project and plugins from `PWD`, not the subprocess cwd argument).
- **Verified live, end to end, not left at "should work":** a real edit (`hello.txt`), a real commit, and a real Entire Checkpoint — `entire checkpoint list` showing `checkpoints: 1`, `entire checkpoint explain` showing the full transcript linked to that commit. Recorded in **ADR-0005**.
- **Honest limitation found in a second verification run, not hidden:** the cheapest gateway model (Nova Lite) occasionally guesses a Unix-style path on Windows that its own `write` and `bash` tools resolve inconsistently, and gives up after retrying. `student_agent.committed_sha` correctly reported `None` rather than a false success — a model-reliability note, not a pipeline defect, and not a reason to hold the ticket open.
- Closed both #12 and #6. `entire_agent_gemini.py` stays in the repo, unused by the active pipeline but correct and documented — real evidence of a failure recovered from, which this hackathon explicitly asks submissions to show, not something to delete because the plan changed.

### 2026-10-11 — Judge agent (ticket #7)
- Built `pareto_ai/judge.py` (17 new tests, 165 passing overall). Two independent signals per Attempt, per CONTEXT.md's Judge Agent entry: the target repo's own test suite for an objective pass/fail, and an LLM-rubric comparison of the Attempt's diff against the Ground Truth's diff for qualitative Gaps, each mapped to a Module or flagged (`module_topic=None`) when no Module in the Curriculum covers it.
- **A real correctness gap caught before it shipped, not left for a demo to surface:** a fix PR adds its regression test in the same commit as the fix, so running the suite against an Attempt that changed nothing at all would still only exercise tests that already existed before the bug was found — a trivial pass. `apply_ground_truth_tests` checks out just the Ground Truth's test files (never its non-test files, which would hand the Attempt the fix itself) onto the Attempt's tree before the suite runs, so "passed" means the Attempt's own code satisfies the real regression test.
- **No extra GitHub fetch needed for either diff.** An Attempt's commit and a Ground Truth's merge commit both live in the same full clone `student_agent.clone_isolated_workspace` already made, so `git diff` inside that same workspace produces both the Attempt's diff and the Ground Truth's diff directly.
- **ADR-0002 applied as written, not just cited:** the rubric call is on the refusing side — a truncated or unparseable response raises `JudgeGradingError` (retried once) rather than reading as `()` Gaps, which the ADR calls out by name as the one place this project cannot afford invisible degradation, since the pass rate is its central claim.
- Ran `/code-review` (Standards + Spec) before committing: Standards found no hard violations; Spec's one actionable finding was that the `AGENT/Judge` neatlogs span sat on the whole per-Attempt orchestrator, which would have made a multi-minute `npm ci`/`npm test` run read as part of an LLM-agent span. Moved the span onto `grade_gaps` alone — the one function that actually calls the LLM — matching `curriculum.py`'s one-span-per-call precedent.
- Pure core (`is_test_file`, `select_test_files`, `parse_gaps`, `_graded`, `grade_gaps`'s no-diff shortcut) is TDD'd; running the real suite, the real `git diff`s, and the live rubric call are smoke-tested only via `main()`, per the project's established pattern — these need the real repo, git history, and LLM on hand, which unit tests cannot stand in for.
- Closed #7.

### 2026-10-11 — The Pareto Table ranks by Demand Weight, from real demand Sources (ticket #11)
- **Replaced the six documentation placeholders** with three demand Sources from the research file (commit `0e20e96`). Each was fetch-verified with the Analyst's own fetcher, and each one's weighted content sits inside the 5000-char cap: **O*NET 15-1299.07** has 17 rated tasks at offsets 2,539–4,619, the **OWASP Smart Contract Top 10 (2026)** has SC01–SC10 at 2,341–2,686, and **Cyfrin SSCD+**'s objectives start at 495. The research had left Cyfrin's terms open. No terms-of-use document is reachable from its page, footer or sitemap, and `robots.txt` permits `/certifications/`.
- **OWASP SCWE and EEA EthTrust were left out on purpose.** They would add security entries but no weight, which is the security-bias trap ADR-0003 warns about. The Top 10 counts as the one OWASP signal.
- **`ParetoEntry.frequency` became `demand_weight`.** Each Source declares its **Demand Scale** (a new glossary term: a Rating, a Rank, or none) and whether it measures the whole Target Skill. Demand Weight is the mean of each report, read as a fraction of its scale, over the Sources entitled to weigh the skill. Silence from a whole-skill Source counts as 0; silence from a Source covering one part is left out. That is `CONTEXT.md`'s absence rule turned into arithmetic: a sum or a max would make the rule do nothing. Recorded as **ADR-0006**.
- **Live result:** 24 distinct Demand Weights across 36 entries, against 45 of 45 tied with documentation. The top 8 by Demand Weight shared nothing with the first 8 alphabetically, which is the acceptance criterion the flat table failed. The only zero-weight Module topics came in through prerequisite closure.
- **`/code-review` found four real defects, all fixed before commit:**
  1. The pure core let a whole-skill Source's citation with an unreadable demand escape that Source's 0. Reproduced, it scored 1.0 instead of 0.5, beating O*NET's own 0.9. Such a citation is now left out as silence, recorded on `ParetoTable.unreadable_citations`, and printed per Source.
  2. The alias merge was allowed to fail quietly because a failure "shows up in the spread". That stopped being true once the table stopped counting, so a failed merge would now be invisible. It now refuses after one retry, per ADR-0002.
  3. The extractor asked for "5-10" skills, but O*NET rates 17 tasks, so any task the extractor skipped was scored as O*NET reporting no demand. It now asks for every rated item, with the token budget raised to 2048.
  4. A whole-skill Source whose extraction failed still counted its silence against every skill. Now only a Source that reported something readable does.
- **First typecheck in this project:** pyright (`npx -y pyright@1.1.390`) on the changed files found one real issue in new test code (fixed) plus a pre-existing stub complaint about `sys.stdout.reconfigure`.
- 181 tests passing; `test_analyst.py` went from 16 to 32. Closed #11.
- **The honest weak spot is filed as #13, not hidden.** O*NET is the only whole-skill Source with a Demand Scale, so its occupation-level tasks outrank every OWASP item: "dashboard development" (0.64) beats "access control" (0.50). Module topics come out as "risk evaluation" and "data requirement analysis". The ranking is faithful to the domain model; it is the model plus the available Sources that yields coarse Modules. That is the builder's decision to make, not a code fix.

## Known limitations and next steps

**Built and closed:** Analyst (#2), Curriculum (#3), Proof-of-Skill Task sourcing (#4), RAG retriever (#5), Student Agent + Entire integration (#6, #12), Judge agent (#7), real demand Sources and Demand Weight (#11). 181 tests passing.
**Not started:** Round orchestrator (#8), rendering (#10), cfo.ai business plan (#9).
**Open:** #13, a domain decision on O*NET's weight (run `/grill-with-docs` before building it); #14, the Module Resource fallback (`ready-for-agent`).

- **The Pareto Table's ranking is now real but coarse, and that is the biggest open gap (#13).** O*NET is the only Source that both has a Demand Scale and measures the whole Target Skill, so its silence counts against every skill it doesn't name. Its tasks are occupation-level ("Test the security and performance of blockchain infrastructures"), not Solidity-level. As a result, all 17 O*NET tasks outrank OWASP's first place, and the top-20% cut is entirely occupation-level work. The mean behind Demand Weight is also not monotonic: O*NET 90 plus OWASP's tenth place scores 0.5, below O*NET 90 alone. Options are listed in #13; ADR-0006 says to revisit it first.
- **A failed alias merge now stops the Analyst.** It refuses after one retry, per ADR-0002, instead of quietly producing a split table. That is safer, but it is one more way a live run can abort.
- **Extracted skill names are the model's paraphrases, not the Source's words.** One live run labelled O*NET's 92-rated "Discuss and plan systems with solution architects…" task as "security audits". The weight comes from the Source; the name comes from the model.
- **O*NET attribution is not printed anywhere yet.** It is CC BY 4.0, so #10's rendered report must credit O*NET and USDOL/ETA. That is noted on #10.
- **A Module's fallback Resource can name a demand Source** (for example "O*NET …") when Resource planning fails twice. This is rare, and filed as #14.
- **Proof-of-Skill Task quality:** the candidate pool includes issues whose fix is not code (one run drew *"Release `v5.5.0` has wrong `dev` tag on `npm`"*). A Student Agent cannot meaningfully attempt that and the Judge cannot grade it by running the test suite. The fix is one extra GraphQL field — filter to PRs touching contract or test files — and it matters before #6.
- `PAGE_TEXT_CHARS = 5000` is a *content* decision rather than a token budget. All three configured Sources sit inside it (measured 2026-10-11). It would only matter if the EEA EthTrust checklist were added, since its first requirement sits at offset ~5,868; per-Source caps would serve better then.
- **A Curriculum holds pointers, not prose.** A Module is a topic, what it assumes, and 1-2 links, so what retrieval hands a Student Agent is "this topic, and here is what to read" — not teaching material to learn from. Whether that is enough for an Attempt to succeed is exactly what #6 and #7 will measure, and it is the honest reading of "bounded to the Curriculum" in the meantime.
- **The three local-embedding tests skip rather than fail** where `sentence-transformers` is not installed, since the pure bounding rules are the part that must never go untested and they need no model. A skip is visible in pytest's output, but a run reporting `96 passed, 3 skipped` has not checked the thing those three exist to check — that retrieval is semantic rather than lexical. First run also downloads the MiniLM weights (~90 MB) from HuggingFace.
- **Retrieval cannot say "nothing here covers that".** `retrieve` returns the k nearest Chunks and k is the only bound, so an off-topic question still comes back with k Modules. A `<= 0` similarity floor was tried and removed: measured against a fixture, an off-topic question scored three chunks at -0.008, -0.014 and +0.040, so the sign was noise and the floor was a coin toss that admitted +0.040 anyway. A threshold that meant something would need calibration data this project does not have.
- **No typechecker is configured** in the venv (no mypy/pyright/ruff). Pyright run ad hoc through `npx` (first used 2026-10-11, on the #11 changes) is the closest thing to one. The rest of the codebase has never been checked with it.
- Free-tier Groq is **8000 tokens/minute**, which a full pipeline run exceeds. Handled by waiting out 429s, but it makes end-to-end runs slow — worth knowing before recording a demo.
- **Entire integration done** (tickets #6, #12) — Checkpoints verified live on `entire/checkpoints/v1`; the `entire-graph` Repo Map call (`compute_repo_map`) is wired into the Attempt but not yet exercised in a full end-to-end `student_agent.main()` run against a real Proof-of-Skill Task (only the engine itself was verified, in scratch repos — see the 2026-10-11 entry).
- **Model reliability for the Student Agent's engine:** the cheapest LiteLLM gateway model (Nova Lite) occasionally fails Windows path handling and gives up rather than committing — one verification run succeeded, a second failed this way. Worth a retry-on-failure pass before relying on a single Attempt in a live demo.
- **cfo.ai integration not started** (ticket #9). The untracked `docs/business-plan.md` is the agreed brief for the cfo.ai session (model parameters, cost engine, the questions the model must answer), not the deliverable. The deliverable has to be built in cfo.ai itself, which is blocked on cfo.ai account access.
- No demo video and no #neatHack build-in-public posts yet.
